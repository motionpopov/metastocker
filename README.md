# MetaStocker 🚀

**MetaStocker** is a free stock metadata generator for photographers and videographers. Generate searchable titles, keywords and categories with local AI in your browser, then export CSV files for your stock platforms. Local generation needs no account, subscription or API key. Optional cloud models use your own paid OpenAI API account.

![MetaStocker Interface](assets/metalogo.png)

## ✨ Key Features

- **Multi-Platform Support**: Tailored metadata for **Adobe Stock**, **Envato Elements**, **Shutterstock**, and **Freepik**.
- **Local AI by Default**: Gemma 4 E2B is preselected for first-time visitors. Choose another local vision model or an optional OpenAI model. Explicit model choices are remembered, and selection alone never starts a download.
- **Dynamic Prompts**: Model-specific prompts, including Adobe Stock category IDs generated by local models and GPT-5.6 Luna.
- **Background Processing**: Uses **Web Workers** to handle API requests without freezing the UI, allowing you to process large batches while the tab is in the background.
- **Browser-first**: Original files stay in your browser. OpenAI mode sends selected previews, metadata, and your API key directly to OpenAI. Local mode keeps image processing and metadata generation on your device, with no API key or inference fees.
- **Smart Thumbnails**: 
  - Instant downscaling for images.
  - Automatic frame capture for videos (captures a representative frame at 50% duration).
- **Advanced Controls**:
  - **Batch Comments**: Add context for the AI (e.g., "3D icons", "flat design").
  - **Always-Include Tags**: Force specific keywords to appear at the start of your metadata.
  - **Concurrency Control**: Choose 1–20 requests per local batch or parallel cloud requests.
- **Export Ready**: One-click CSV generation formatted exactly for each stock platform's upload requirements.

## 🛠️ Technology Stack

- **Frontend**: Vanilla JavaScript (ES6+), HTML5, CSS3.
- **Styling**: Static Tailwind CSS 3.4.17 utilities (layout) + custom CSS variables (aesthetics).
- **AI**: OpenAI Chat Completions API; Transformers.js 4.3.0 and ONNX Runtime Web for local models.
- **Aesthetics**: `tsParticles` for a dynamic background and an "Apple-like" premium glassmorphism design.
- **Utilities**: `exifr` for image metadata extraction (IPTC/XMP).

## 🚀 Getting Started

1. **Open the hosted app over HTTPS**, or serve this directory with `python3 -m http.server 8080` and open `http://localhost:8080`. Local models cannot run from a `file://` URL.
2. **Choose a local AI model**. Gemma 4 E2B is selected initially; returning visitors keep their saved choice. To use an optional paid cloud model, choose OpenAI in the model list and enter your API key (kept in session storage for the current browser tab). See the [illustrated API key setup guide](blog/how-to-get-openai-api-key.html).
3. **For a local model, click Download & load** and wait for Ready. Selecting a model alone never downloads it.
4. **Drag & Drop** your photos or videos into the app.
5. **Click Start** and watch the AI attribute your assets in real-time.
6. **Download your CSVs** and upload them to your contributor dashboards.

### Local AI (beta)

| Model | Approximate download | Recommended device memory |
| --- | --- | --- |
| [Qwen3.5 2B](https://huggingface.co/onnx-community/Qwen3.5-2B-ONNX-OPT) | 2.3 GB | 8 GB or more |
| [Gemma 4 E2B](https://huggingface.co/onnx-community/gemma-4-E2B-it-ONNX) | 3.5 GB | 8 GB or more |
| [Gemma 4 E4B](https://huggingface.co/onnx-community/gemma-4-E4B-it-ONNX) | 5.3 GB | 16 GB or more |

Use a current browser with WebGPU and `shader-f16` support, such as Chrome or Edge with graphics acceleration enabled. Memory figures are guidance, not a compatibility guarantee; GPU limits and other open apps also matter. These are vision models, so they can analyze image previews and the representative frame extracted from a video. Text-only Llama/Gemma variants are not suitable for this workflow.

Qwen3.5 2B uses Q4 language weights and an FP16 vision encoder; its download estimate includes both components. Local previews are limited to a 768-pixel longest edge for this model. Thinking is explicitly enabled through its chat template. As the [model authors note](https://huggingface.co/Qwen/Qwen3.5-2B#thinking-mode), this small model can repeat its reasoning. An additive presence penalty of 1.5 discourages repeated tokens without penalizing the input prompt. After at most 512 thinking tokens, the local runtime emits the model's native closing marker and lets it generate its final answer within the remaining 2,048-token total budget. Naturally finished reasoning can end sooner. The runtime prefills an opening JSON brace after reasoning; all metadata values are generated by the model and still validated by the application.

- Downloads begin only with **Download & load**. Progress includes downloading and preparing the model on the GPU. **Cancel download** stops the worker; completed files can be reused when retrying.
- Model files are saved in this site's browser cache. **Unload from memory** releases all prepared workers and GPU sessions while keeping saved weights. **Load model** initializes them again after unloading or reloading the page. **Delete model** releases the selected model and removes its downloaded files from this browser. Other models and metadata are preserved. Stop active work before unloading or deleting. The browser may also evict cached files.
- Local runs use **one worker and one model instance**, including Adobe metadata, Envato fields, Shutterstock categories, and regeneration. **Batch size** selects up to 1–20 requests for one tensor batch; ready requests collect for 120 ms, so an underfilled batch can run without waiting indefinitely. Changing the size does not reload weights. Each request keeps its own image, prompt, thinking and final response. Start with **1–2**: larger batches share model weights but need more working RAM/GPU memory and may be slower or fail. Available GPU memory cannot be reliably measured in the browser, so this is not an automatically qualified hardware limit. A runtime/GPU failure stops the batch and requires reloading; the app never creates extra model copies or switches to a cloud API. **Stop local batch** cancels active and queued local requests and leaves interrupted files queued. Reload the model to resume.
- Gemma combines requests with equal input lengths to avoid a confirmed WebGPU padding regression in the pinned export. Different image proportions or prompt lengths can produce smaller groups, including individual requests. The status shows the actual group size; weights remain shared. See [batching and browser smoke tests](docs/local-ai-batching.md).
- **Thinking is enabled for every local model and every generation stage.** Responses have a 2,048-token budget for Qwen and 4,096 for Gemma, including reasoning. Only the final answer reaches metadata parsing and CSV export; truncated reasoning is rejected. Thinking can increase processing time and memory use.
- Local inference never falls back to OpenAI. Invalid metadata is rejected, with up to two additional attempts for the main metadata response. Short keyword lists can be supplemented by additional image-grounded model responses; duplicate tags are removed and no placeholder keywords are added. Smaller models can fail to follow instructions; review titles, tags, and categories before export.
- The first download fetches a pinned runtime from jsDelivr and public model weights from Hugging Face. No image, prompt, or API key is included in those downloads. Once loaded, inference needs no network. Opening the site and initializing the runtime again may still require internet; this is not an offline PWA.

The allowlisted models, immutable Hugging Face revisions, download estimates, and cache names are in `local-ai.js`. `local-ai-worker.mjs` owns the runtime and GPU sessions. `app.js` routes all generation stages through `callAI`; the cloud adapter rejects local model IDs. Deployment must retain the WebAssembly, jsDelivr, and Hugging Face directives in `_headers` for both the page and worker responses.

### Checks

```sh
node --check app.js
node --check local-ai.js
node --check local-ai-worker.mjs
node --test tests/*.test.js
git diff --check
```

For browser qualification, serve the app with the same CSP as `_headers`, verify that choosing a local model starts no download, then explicitly download and generate metadata from a test image. Check cache reload, cancellation, deletion, unsupported WebGPU, mobile layout, and both themes. Confirm that local generation makes no OpenAI/xAI requests. Automated tests use fake workers for failure paths; they do not replace real WebGPU inference checks.

The September 18, 2026 Chrome check exercised both Gemma downloads, cached reloads without model-network requests, E4B with all export fields, and two simultaneously active E2B workers with thinking. Both files completed; cancelling a separate two-file run returned both files to the queue. Download cancellation and model-scoped cache deletion also passed. This verifies the integration, not semantic accuracy: on the public animal photo used for testing, the models misidentified the species. Local mode remains beta and metadata needs human review. Other browsers, GPUs, and large thread counts have not been qualified.

Qwen3.5 2B was checked in Chrome with the final thinking budget, JSON prefix, and presence penalty settings: two simultaneously active workers completed two test files with 20 unique tags, numeric Adobe categories, and valid Envato and Shutterstock fields. Inference made no network requests. A separate cache check loaded the model twice, including after a page reload, without Hugging Face requests. The checks also cover explicit downloading, persisted selection, and desktop/mobile layouts. The model can still produce redundant keyword variants and inaccurate descriptions; successful export validation does not establish semantic accuracy.

The v2.9 browser check confirmed Gemma 4 E2B as the first-visit default, remembered local and cloud choices, no automatic model downloads, and desktop/mobile layouts in both themes. With an actual cached Qwen model, **Unload from memory** closed its GPU worker while retaining downloaded files; **Load model** reopened it without model-network requests. **Delete model** closed the replacement worker and removed only Qwen's cache, preserving another model's cache, unrelated browser data, and settings. All 19 regression checks passed.

### Rebuilding styles

After adding or changing Tailwind utility classes in HTML or `app.js`, rebuild the checked-in production stylesheet:

```sh
npx --yes tailwindcss@3.4.17 -i tailwind.input.css -o tailwind.generated.css --content './index.html,./blog/**/*.html,./app.js' --minify
```

## 📁 Project Structure

- `index.html`: The main entry point and UI layout.
- `app.js`: Core logic, API integration, and background worker.
- `local-ai.js`, `local-ai-worker.mjs`: Local model catalog, download lifecycle, browser cache, and GPU inference.
- `style.css`: Custom premium styling and design tokens.
- `tailwind.input.css`: Tailwind build entry point.
- `tailwind.generated.css`: Minified static Tailwind utility bundle used in production.
- `blog/`: Articles and guides for stock contributors.
- `Update.bat`: A handy utility for Git operations.

## Owner analytics

The protected [owner dashboard](https://metastocker.net/admin/) shows first-party anonymous counters. No persistent visitor ID, photos, filenames, prompts, generated metadata or API keys are collected. A random page code exists only in memory. The public [privacy page](https://metastocker.net/privacy.html) provides opt-out; DNT/GPC and owner visits are excluded. Analytics requests may be sent while local inference runs, but contain only counters and approved categories. Local AI itself still runs entirely in the browser. See [metrics, access, backups and operation](docs/analytics.md).
