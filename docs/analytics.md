# Статистика MetaStocker

Админка: https://metastocker.net/admin/. Интерфейс владельца на русском, вход по отдельному паролю. Пользователям регистрация не нужна.

## Что измеряем

Источник всех показателей — собственные события `analytics.js`, явные вызовы в `app.js` и тот же счётчик на страницах блога. С сентября 18, 2026 старый GoatCounter заменён этим сбором; история GoatCounter не импортируется. Цели по конверсии и скорости не задаются до появления реальной базы сравнения.

| Показатель | Определение и назначение | Ограничение |
| --- | --- | --- |
| Посещения | Число отдельных открытий генератора или страницы блога. Показывает объём трафика | Это не уникальные люди; переход, обновление, новая вкладка дают новое открытие |
| Успешные обработки | `file_success`: готовые метаданные для всех запрошенных форматов одного файла | Не проверяет смысловую точность описания; повторная генерация считается снова |
| Экспорты CSV | Нажатия кнопки конкретного CSV после формирования файла | Не подтверждает сохранение файла на диске или отправку на сток; повторное нажатие считается снова |
| Доля успеха | Успешные / (успешные + ошибки). При нулевом знаменателе — прочерк | Отмены и незавершённые попытки исключены |
| Популярные модели | Число `file_start` по модели, затем успехи, ошибки, время и средняя параллельность | Выбор по умолчанию, просмотр и загрузка не считаются обработкой |
| Время обработки | Среднее время завершившихся успешно попыток, от начала подготовки файла до готовности всех выбранных форматов | Сравнивает разные устройства и наборы форматов; не является оценкой чистой скорости модели |
| Путь до CSV | Открытия генератора → импорт → запуск → успех → экспорт в пределах одного открытия | Когорта открытий, начавшихся в период, события до конца периода; не связывает блог с генератором |
| Страны / источники / страницы | Число открытий по приблизительной стране, домену источника, известному пути страницы | VPN влияет на страну; прямой переход включает неизвестный источник. Показываются первые 30 групп |
| Модели: загрузка | Начало подготовки, готовность, ошибка, отмена | Включает загрузку из кеша и подготовку дополнительных потоков; это не счётчик скачанных гигабайтов |
| WebGPU | Результат первой реальной проверки совместимости локальных моделей за открытие | Проверка может не происходить при сохранённом выборе облачного API |

График и операции используют день получения события сервером в **Europe/Warsaw**. «Сегодня», 7/30/90 дней включают текущий день. Период ограничен последними 90 календарными днями. Воронка использует дату начала открытия, поэтому её значения не обязаны равняться суммам операций. Связь только по случайному коду одной страницы, который обновляется при перезагрузке и не позднее 24 часов. UUID события обеспечивает дедупликацию повторной доставки.

## Приватность и точность

- Нет постоянного ID, аналитических cookies, fingerprinting, связи между посещениями, оценки возвращаемости или уникальных людей.
- В базу не попадают IP, полный User-Agent, фото, названия файлов, промпты, результаты, API-ключи и произвольные тексты ошибок. Сервер отклоняет неизвестные поля, модели, страницы и коды ошибок. Клиент отправляет лишь разрешённые поля.
- IP используется в памяти для ограничения запросов и локального GeoIP, сохраняется только код страны. Используется закреплённая база `@ip-location-db/geo-whois-asn-country-mmdb@2.3.2026061719` (CC0) и `mmdb-lib@3.0.2` (MIT); без внешнего запроса с IP. База приблизительная, от 2026-06-17. При обновлении версии проверить формат и лицензию нового пакета, обновить lock-файл и дату в интерфейсе.
- Хранение событий — 90 календарных дней. Очистка и резервное копирование проверяются каждый час и при старте. Резервные копии удаляются после 7 дней; копии могут сохранять уже удалённые события дополнительно до этого срока. При остановленном сервисе очистка возобновится после запуска.
- Do Not Track, Global Privacy Control, известные боты и настройки отказа исключаются. Страница `/privacy.html` управляет булевой настройкой `metastocker_stats_disabled`. После входа владельца эта настройка включается; сервер дополнительно исключает запросы с действующей owner-cookie. Для проверки публичного сбора использовать отдельный браузерный контекст.
- Аналитика не блокирует AI, не отправляет содержимое, не повторяет AI-запросы и не включает fallback. Потерянная связь, блокировщик, закрытая вкладка или браузер могут не доставить событие. Цифры показывают наблюдаемое использование, а не гарантированную перепись всей аудитории. Публичный collector не доказывает подлинность действий; ограничения частоты лишь уменьшают злоупотребления.
- Страница приватности описывает этот сбор. Загрузка модели по-прежнему идёт из Hugging Face/jsDelivr; инференс работает в браузере. API-модели по-прежнему обращаются к выбранному API напрямую.

## Сервер и доступ

`metastocker-web` отдаёт сайт и проксирует только `/api/analytics`, `/admin` и `/admin/*` в `metastocker-analytics:8081` через отдельную внутреннюю Docker-сеть `metastocker_stats`. Публичного порта у backend нет. Общий Caddy и соседние сайты не меняются. Он перезаписывает `X-Forwarded-For`; статический Caddy передаёт этот заголовок backend без изменения. Backend доверяет последнему адресу только при `TRUST_PROXY=1` в этой закрытой схеме.

- Код сервиса и админки: `/opt/metastocker/current/server` (образ собирается из конкретного релиза).
- Постоянная SQLite: `/opt/metastocker/data/analytics.sqlite`, WAL, uid 1001, каталог 0700.
- Ежедневные и предрелизные online backup: `/opt/metastocker/data/backups/`. Не копировать работающий SQLite через `cp`.
- Секреты: `/opt/metastocker/secrets/auth.json`, uid 1001, 0600, каталог 0700. Только соль, scrypt-хеш пароля и ключ подписи сессий. Пароль на сервер не копируется.
- Cookie владельца: HttpOnly, Secure, SameSite=Strict, 8 часов, подписана случайным ключом. Пароль/сессии не логируются. Запросы записи проверяют Origin. Вход ограничен по частоте. Смена ключа инвалидирует все сессии; обычный выход удаляет cookie в браузере.
- `server/server.mjs` не пишет access log и не печатает тело запроса/произвольные ошибки. Аналитические IP не добавляются в логи веб-сервера. Существующие инфраструктурные журналы соседних приложений не меняются.

Первичная подготовка (Node 24+, приватные новые пути; скрипт не перезаписывает существующие файлы):

```sh
mkdir -p .deploy/owner-access
chmod 700 .deploy/owner-access
node server/init-auth.mjs .deploy/owner-access/auth.json .deploy/owner-access/password.txt
ssh vintage-shop-prod 'mkdir -p /opt/metastocker/secrets /opt/metastocker/data && chown 1001:1001 /opt/metastocker/secrets /opt/metastocker/data && chmod 700 /opt/metastocker/secrets /opt/metastocker/data'
scp .deploy/owner-access/auth.json vintage-shop-prod:/opt/metastocker/secrets/auth.json
ssh vintage-shop-prod 'chown 1001:1001 /opt/metastocker/secrets/auth.json; chmod 600 /opt/metastocker/secrets/auth.json'
```

Сохранить пароль из локального файла в менеджер паролей. Нельзя коммитить файлы доступа, включать их в public или выводить в логи. Ротация: создать новую пару файлов в новом приватном каталоге, сохранить прежний auth.json в root-only конфигурационной резервной копии, заменить серверный auth.json, выполнить `docker compose -p metastocker -f /opt/metastocker/compose.yaml up -d --force-recreate --no-deps analytics`. Удалить старую локальную копию пароля после сохранения новой. Не переиспользовать доступы других продуктов.

## Обновление, проверки, откат

Обычный выпуск описан в [deployment.md](deployment.md). Требуется Node 24+. Переменная `METASTOCKER_NODE` позволяет указать конкретный бинарник. `npm ci` устанавливает только две закреплённые GeoIP-зависимости; локальные модели на сервер не устанавливаются.

```sh
(cd server && npm ci --ignore-scripts --no-audit --no-fund)
node --test tests/*.test.js tests/*.test.mjs
python3 -m unittest discover -s tests -p test_deploy.py
bash deploy/deploy.sh vintage-shop-prod
```

Перед активацией скрипт сохраняет Compose и указатель релиза, делает согласованный online backup существующей SQLite, собирает образ backend, затем переключает только два сервиса MetaStocker. Общий Caddy не перезапускается. Ошибка активации возвращает предыдущий код; данные остаются вне релизов. Схема v1 создаётся только добавлением таблиц и индексов.

`bash deploy/rollback.sh vintage-shop-prod [release-id]` возвращает код, сохраняя текущую базу. При откате на v2.10 collector останавливается, данные остаются на диске; при следующем обновлении снова доступны. После отката на старую версию без аналитики автоматическая очистка временно не работает. Если будущая миграция окажется несовместимой, сначала подготовить совместимый откат схемы; скрипт намеренно не заменяет свежую базу старой копией.

Восстановление повреждённой базы — отдельная операция с остановленным backend: сначала сделать копию повреждённых `analytics.sqlite*`, проверить `PRAGMA integrity_check` у выбранной резервной копии, убрать только текущие WAL/SHM после остановки, восстановить SQLite, вернуть владельца 1001 и режим 0600, запустить только analytics и проверить админку. Восстановление копии теряет события после её времени; не выполнять это вместо обычного отката кода.

Публичная проверка `deploy/verify_production.py` проверяет хеши, основные страницы, приватные пути 404, защищённые endpoints 401, редирект входа и `no-store`. Unit/integration проверки покрывают схему и отсутствие содержимого, SQL-агрегацию, параллельные попытки, дедупликацию, отмены, календарные дни, очистку, online backup, GeoIP, auth, Origin, DNT/GPC, ботов, владельца и ограничение частоты.

Браузерная проверка: пустая и заполненная админка, desktop/375px, обе темы, график и фильтры, ошибка сервера, вход/выход, импорт → параллельная обработка → CSV, отсутствие содержимого в событиях, отказ от сбора. Тестовые AI-ответы для проверки событий использовать только локально; они не доказывают качество реальных моделей. Не оставлять искусственные события в production.
