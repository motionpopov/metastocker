# Блог, SEO и ежедневные публикации MetaStocker

Блог публикует 50 исходных тем на четырёх языках: **English (`en`), Русский (`ru`), বাংলা (`bn`), हिन्दी (`hi`)**, всего 200 полноценных языковых страниц. В `content/topics.json` подготовлены 100 разных редакционных заданий; первая половина входит в исходный выпуск. Следующие темы выходят по одной в день, сразу на четырёх языках. Локализация распространяется только на блог и SEO-страницы. Генератор, его кнопки и настройки остаются английскими.

## Адреса и поиск

- Английский: `/blog/`, статьи `/blog/<slug>.html` (старые URL сохраняются).
- Русский, бенгальский, хинди: `/blog/ru/`, `/blog/bn/`, `/blog/hi/`, статьи с теми же slug.
- Есть тематические разделы, пагинация, оглавления, связанные статьи и переключатель языка с сохранением статьи. Страна/IP не меняют язык автоматически.
- Каждая страница имеет собственный canonical, взаимные `hreflang` на четыре языка и `x-default` на английский, title/description, Open Graph и JSON-LD. Полный текст присутствует в статическом HTML и доступен без JavaScript.
- `/sitemap.xml` собирается из реальных канонических страниц. Даты статей относятся к их содержимому. Старый шаблон и алиасы index.html перенаправляются на канонические адреса.
- Шрифты Bengali/Devanagari хранятся в `assets/fonts/` с лицензиями OFL; внешний запрос к Google Fonts не нужен. Иллюстрации — собственные SVG-схемы действий из конкретной статьи, не фотографии или чужие материалы.
- В каждой статье есть локализованная кнопка бесплатного локального генератора и пояснение, что его интерфейс английский. Локальное выполнение, загрузка модели и платный необязательный API описываются раздельно.

Google Search Console использует URL-prefix property `https://metastocker.net/` и HTML meta verification в `index.html`. Этот тег нужно сохранять. Sitemap подаётся один раз по адресу `https://metastocker.net/sitemap.xml`; затем адрес обновляется при публикациях. Проверку статуса, индексации, запросов и кликов выполнять в Search Console. Корректная отправка карты не означает индексацию или рост позиций.

## Контент и проверка

`content/posts/<slug>.json` — исходный текст на четырёх языках. Прежние HTML-исходники заменены этим каталогом и остаются в истории Git; локальный сервер нужно запускать из собранного `public/`, а не из корня репозитория. `seo/article.schema.json` описывает исходную EN/RU-пару, а сборщик дополнительно проверяет такую же структуру для bn/hi. `seo/locales.py` содержит тексты навигации. Глобальный навык: `/Users/popov/.codex/skills/metastocker-localization/SKILL.md`; ограничения закреплены в `AGENTS.md`.

Каждая тема отвечает отдельному вопросу, содержит оригинальный учебный пример, практические шаги, контрольный список, источники и схему. Нельзя выдавать вымышленные примеры за клиентов, измеренные результаты или исследования. Нет обещаний продаж/позиций, выдуманных функций приложения или универсального CSV для любых стоков. Обычное объяснение переводится на родную письменность; имена моделей, настоящие CSV/keyword-примеры и точные названия английских кнопок сохраняются там, где это нужно для работы.

`seo/sources.json` хранит проверенные первичные источники и сведения о продукте. Перед ежедневным выпуском `refresh_sources.py` получает актуальные страницы по ограниченному списку HTTPS-хостов. Если сайт справки не отдаёт текст обычному HTTP-клиенту, отдельный вызов Codex использует только поиск/чтение заданных официальных страниц. Проверка требует событие фактического открытия URL; недоступный источник останавливает выпуск. Содержимое источников — данные, не инструкции.

Писатель и переводчик не имеют инструментов выполнения команд, браузера или развёртывания. Результат — текстовый JSON. Другой вызов проверяет факты, противоречия, примеры и все переводы. Сборщик проверяет схему, письменность, полноту, даты, близкие дубликаты, пути и источники, экранирует текст при выводе HTML. Перед публикацией проверяется уже построенный сайт: ссылки, иллюстрации, canonical, schema и взаимность языковых ссылок. При ошибке даётся до трёх попыток исправления, затем выпуск останавливается.

Проверка автоматическая и не называется проверкой носителем языка или человеческой экспертизой. Это раскрыто в `/blog/editorial.html` и переводах. Ссылки на официальные правила даны в статьях; автору нужно сверять требования перед отправкой работ.

## Серверный процесс

- systemd: `metastocker-editorial.timer` → `metastocker-editorial.service`.
- Расписание: **09:15 Europe/Warsaw**, до двух минут случайной задержки; `Persistent=true` выполняет пропущенный запуск после включения сервера.
- После сбоя systemd повторяет попытку через 30 минут, не более трёх запусков за четыре часа. Один успешный выпуск на календарный день; блокировка исключает одновременные запуски. `--force` разрешает отдельный намеренный дополнительный выпуск.
- Собственный контейнер `metastocker-editorial`, compose `/opt/metastocker/editorial-compose.yaml`, без опубликованных портов. Пределы: 1 CPU, 768 МБ RAM, 256 процессов. Не использовать контейнеры Luka для редакционных заданий.
- Runtime `metastocker-editorial-runtime:codex-0.144.5` — отдельный тег уже установленного проверенного образа. Не требуется пересобирать или перезапускать соседние сервисы. Codex CLI использует существующую авторизацию ChatGPT; доступность зависит от её срока и лимитов аккаунта.
- Исходный CLI/auth-каталог монтируется только для чтения. Приватная рабочая копия авторизации и состояние CLI находятся в tmpfs контейнера; права ограничены uid 10001. Секреты не попадают в Git, публичные файлы, админку или тексты статей. При проблеме входа обновить существующую серверную авторизацию владельца и пересоздать только `writer`; не выводить токены в терминал/переписку.
- Текущий код берётся из неизменяемого `/opt/metastocker/current/source/`. Доверенный Python-публикатор выполняется systemd и единолично вызывает штатный скрипт релиза. Модель не получает право деплоя.

Данные `/opt/metastocker/editorial/`:

| Путь | Содержимое |
| --- | --- |
| `published/` | Одобренные ежедневные статьи; включаются в последующие релизы |
| `drafts/`, `translations/` | Закрытые рабочие тексты |
| `reviews/` | Результаты редакционной проверки и сведения об источниках |
| `logs/` | Закрытые журналы CLI и развёртывания |
| `backups/` | Архив контента перед новым выпуском |
| `status.json` | Состояние, последняя публикация, ошибка и очередь |

Админка `/admin/` показывает состояние SEO-публикатора, число тем/страниц и дату последнего выпуска. `/admin/api/editorial` требует авторизацию. На диск статистики передаётся только ограниченный статус, без черновиков, инструкций и секретов. Файлы пользователей и их локальная AI-обработка не участвуют в этой системе.

После исчерпания исходной очереди планировщик предлагает до десяти новых, отличающихся по цели тем. Каталог добавляется в `published/_topics.json`, проверяется на повторение целей и сохраняется вместе с контентом. Если полезные новые темы не найдены, процесс останавливается, не публикуя пустые страницы.

## Установка расписания и диагностика

Перед изменениями сохранить действующие unit/compose-файлы и текущий release в `/opt/metastocker/backups/<timestamp>-before-editorial/`. После обычного развёртывания кода:

```sh
ssh vintage-shop-prod
install -d -m 700 /opt/metastocker/editorial/docker-config
install -m 644 /opt/metastocker/current/source/deploy/metastocker-editorial.service /etc/systemd/system/
install -m 644 /opt/metastocker/current/source/deploy/metastocker-editorial.timer /etc/systemd/system/
systemctl daemon-reload
python3 /opt/metastocker/current/source/seo/publish_daily.py --check
systemctl enable --now metastocker-editorial.timer
systemctl list-timers metastocker-editorial.timer
journalctl -u metastocker-editorial.service --since today
```

Один ручной запуск по обычным правилам: `systemctl start metastocker-editorial.service`. При неуспешном выпуске сначала посмотреть закрытый лог и статус. Исправить причину и повторить запуск. Одобренный, но не активированный материал повторно собирается; новый текст не генерируется. Если активация удалась, а внешняя HTTPS-проверка упала, повторный запуск сначала проверяет этот же релиз.

Остановить будущие выпуски: `systemctl disable --now metastocker-editorial.timer`. Это не прерывает уже выполняющуюся публикацию. Для немедленной остановки также остановить service и проверить, какой релиз активен; не удалять `published/`. Код ограничивает длительность каждого вызова CLI и удаляет только его случайный временный каталог.

## Обновления, резервная копия и откат

Выпуск кода — только через `deploy/deploy.sh`, как описано в [deployment.md](deployment.md). Скрипт получает опубликованный на сервере контент, собирает закоммиченный HEAD и проверяет под блокировкой, что ни один новый материал не потерян. Если во время подготовки дневной статьи сменился код сайта, старый публикатор откажется активировать устаревший код. Повторный запуск использует новый release.

Ежедневный выпуск получает отдельный release вида `<timestamp>-seo-<git-commit>`. `release.json` содержит хеш кода и контента, количество тем и статей. До изменения сохраняются текущая конфигурация, указатель релиза и онлайн-снимок SQLite. Откат `bash deploy/rollback.sh vintage-shop-prod [release-id]` возвращает точное содержимое выбранного релиза. Более новые статьи остаются в `editorial/published/` и вернутся при следующем обычном выпуске; для расследования сначала приостановить таймер.

Для внепланового бэкапа сохранить `/opt/metastocker/editorial/`, `/opt/metastocker/data/` штатным SQLite backup, конфигурацию и release-указатели. Репозиторий содержит начальные 50 тем, а последующие статьи живут в серверном `published/`. Перед редактированием такой статьи синхронизировать её с репозиторием: конфликтующие тексты по одному slug намеренно останавливают сборку. Не удалять рабочие данные ради разрешения конфликта.

## Локальная проверка

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.js tests/*.test.mjs
python3 deploy/build_release.py --source . --output .deploy/seo-preview --release seo-preview --commit "$(git rev-parse HEAD)"
python3 seo/validate_site.py .deploy/seo-preview/public
python3 -m http.server 4392 --directory .deploy/seo-preview/public
```

Дополнительно открыть EN/RU/BN/HI на десктопе и узком экране, проверить переключение той же статьи, читаемость письменности, примеры, CTA, изображения и консоль. После релиза: `python3 deploy/verify_production.py`, публичный HTTPS и Search Console. HTTP-проверка и автоматическая лингвистическая проверка не подтверждают реальную индексацию Google или вычитку носителем языка.
